# NixOS Configuration Repo

## Project Structure

This is a NixOS flake-based configuration managing multiple machines.

- **`flake.nix`** — Entry point. Defines inputs (nixpkgs 25.05, nixpkgs-unstable, home-manager) and three host configurations.
- **`modules/`** — Shared NixOS modules (common.nix, desktop.nix, networking.nix, dev-tools.nix, gaming.nix, nvidia.nix, home.nix).
- **`hosts/`** — Per-machine configs, each with `default.nix`, `hardware-configuration.nix`, and a `home/` directory for home-manager settings.
- **`config/`** — Dotfiles and app configs (waybar, rofi, MangoHud, hyprland, oh-my-posh, etc.).
- **`rebuild.sh`** — Rebuild script: formats with `alejandra`, runs `nixos-rebuild switch --flake .`, and auto-commits on success.

## Hosts

- **`bee-pc`** — Desktop PC. Uses all `commonModules`.
- **`bee-gpd`** — GPD handheld device. Uses `commonModules` + `nvidia.nix`. Has Thunderbolt, Joy-Con, Bluetooth, and tmux config.
- **`homelab`** — Server. Minimal config, does NOT use `commonModules` (only the unstable overlay + its own host module).

## Conventions

- **Formatter:** `alejandra` (not `nixfmt`). The rebuild script auto-formats before building.
- **Unstable packages:** Available via `pkgs.unstable.*` through an overlay defined in `flake.nix`.
- **Main user:** `bee` (defined in `modules/common.nix`).
- **Shell:** zsh with oh-my-posh theming.
- **Desktop environment:** Hyprland (Wayland compositor) with waybar, rofi, and catppuccin-mocha theme.
- **Nix style:** Use `with pkgs;` for package lists. Use `let/in` blocks for local bindings. Keep inline comments for non-obvious packages (e.g. `brightnessctl #brightness control`).
- **Module placement:** Shared config goes in `modules/`. Machine-specific config goes in `hosts/<name>/default.nix`. Don't put host-specific settings in shared modules.
- **Home-manager vs system-level:** Use home-manager (`hosts/<name>/home/`) for user-level dotfiles, shell config, and per-user programs. Use NixOS system options for services, boot, hardware, and system-wide packages.
- **Don't edit `hardware-configuration.nix`:** These are auto-generated by `nixos-generate-config`. Manual hardware/boot tweaks go in the host's `default.nix`.
- **Unstable package policy:** Default to stable packages. Only use `pkgs.unstable.*` when the stable version is too old, missing features, or broken.
- **Config file management:** Dotfiles live in `config/` and are referenced via `builtins.readFile` or home-manager's `xdg.configFile`. Don't inline large configs in `.nix` files.

## Documentation & Package Rules

- **Always reference official Nix documentation** (nixos.wiki, nix.dev, NixOS options search, Nixpkgs manual) when suggesting configuration changes. Cite the source URL when possible.
- **Verify packages exist before adding them.** Search https://search.nixos.org/packages to confirm a package name is real and available in the correct channel (stable or unstable) before including it in any config.
- **Never hallucinate package names.** If unsure whether a package exists, look it up first rather than guessing.
- **Check NixOS options first.** Before writing custom systemd services or wrappers, search https://search.nixos.org/options to see if a built-in NixOS option already exists.
- **Target the right host.** Always confirm which host a change applies to. Remember `homelab` does NOT use `commonModules`, so shared module changes won't affect it.
- **Flake lock updates.** `nix flake update` should be done intentionally, not as part of routine rebuilds. Call out when bumping inputs.

## Debugging Rebuilds

- **Build log:** `nixos-switch.log` (gitignored) in the repo root contains the full output from the last `nixos-rebuild switch`. When a rebuild fails, read this file to diagnose errors before suggesting fixes.

## Workflow

1. Edit `.nix` files or configs
2. Run `rebuild` to format, build, and auto-commit
3. The commit message is automatically set to the current NixOS generation metadata
