# Secrets (sops-nix)

This repository keeps all secrets encrypted at rest with [sops](https://github.com/getsops/sops)
and [age](https://github.com/FiloSottile/age), decrypted on each host at activation by
[sops-nix](https://github.com/Mic92/sops-nix).

## Model

- **Per-host key.** Every host has its own age key at `/var/lib/sops-nix/key.txt`
  (`0600 root:root`), provisioned out-of-band before first activation. The key is never
  committed and never generated by NixOS.
- **Split ciphertext.**
  - `secrets/common.yaml` — shared material (Tailscale auth key, k3s server token),
    encrypted to the hosts that consume it.
  - `secrets/hosts/<host>.yaml` — material unique to one host.
- **Recipient routing.** `.sops.yaml` declares one named anchor per recipient and
  `creation_rules` that map each file path to its recipients.
- **Host wiring.** `modules/sops.nix` sets the key path. Each host sets
  `sops.defaultSopsFile`; a single secret can override with `sops.secrets.<name>.sopsFile`.

### Files

| Path | Contents | Recipients |
| --- | --- | --- |
| `secrets/common.yaml` | `tailscale_auth_key`, `k3s_server_token` | admin + Tailscale/k3s consumers |
| `secrets/hosts/protecli-vault.yaml` | `mullvad_wg_private_key`, `ap_password` | admin + `protecli-vault` |
| `secrets/hosts/<host>.yaml` | host-unique material | admin + that host |
| `.sops.yaml` | recipients + rules (public keys only) | — |

## Key generation

Private keys live on the operator machine at `~/.config/sops/age/hosts/<host>.key`
(`0600`), never in the repo.

~~~bash
scripts/generate-age-keys.sh                      # all fleet hosts
scripts/generate-age-keys.sh homelab protecli-vault
~~~

Each key's public half is printed; paste it into `.sops.yaml` as the matching anchor.

## Provisioning a key to a host

~~~bash
scripts/provision-host-key.sh <host-or-ip> [ssh-user]
~~~

This creates `/var/lib/sops-nix` (`0700 root:root`) and installs the key as
`/var/lib/sops-nix/key.txt` (`0600 root:root`). To do it manually:

~~~bash
ssh bee@<host> 'sudo install -d -m 0700 /var/lib/sops-nix'
ssh bee@<host> 'sudo tee /var/lib/sops-nix/key.txt >/dev/null' < ~/.config/sops/age/hosts/<host>.key
ssh bee@<host> 'sudo chown root:root /var/lib/sops-nix/key.txt && sudo chmod 0600 /var/lib/sops-nix/key.txt'
~~~

## Editing secrets

Use the admin key to edit a file in place (values are re-encrypted on save):

~~~bash
SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt nix shell nixpkgs#sops -c sops secrets/common.yaml
~~~

## Adding a host

1. Generate a key: `scripts/generate-age-keys.sh <host>`.
2. Add an anchor `- &<host> age1...` under `keys:` in `.sops.yaml`.
3. Add `creation_rules` for `secrets/hosts/<host>.yaml` (`[*admin, *<host>]`) and add the
   host to `secrets/common.yaml`'s recipient list if it needs shared material.
4. Re-wrap the affected ciphertexts: `sops updatekeys secrets/common.yaml`.
5. Provision the key: `scripts/provision-host-key.sh <host>`.
6. Set `sops.defaultSopsFile = ../../secrets/hosts/<host>.yaml;` (or `common.yaml`) in the
   host's `default.nix`.

## Rotating or replacing a recipient key

Replace the host's public anchor in `.sops.yaml`, then re-wrap every file that host can
read:

~~~bash
SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt nix shell nixpkgs#sops -c \
  sops updatekeys secrets/common.yaml secrets/hosts/<host>.yaml
~~~

## Offline backup

Back up **all** per-host private keys plus the admin key to a single encrypted bundle and
store it on an offline medium of your choosing (encrypted USB, password manager attachment,
printed paper key). The repo and CI never hold a copy.

~~~bash
tar -C ~/.config/sops -czf - age | \
  age -R <offline-recipient.txt> -o fleet-age-keys-$(date +%F).tar.gz.age
~~~

Store `fleet-age-keys-<date>.tar.gz.age` and the offline identity separately. Record the
backup location and date in your password manager.

## Recovery: a host key is lost

1. Generate a replacement: `nix shell nixpkgs#age -c age-keygen -o /tmp/<host>.key`.
2. Replace that host's anchor in `.sops.yaml` with the new public key
   (`age-keygen -y /tmp/<host>.key`).
3. Re-wrap the affected files (admin key required):

   ~~~bash
   SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt nix shell nixpkgs#sops -c \
     sops updatekeys secrets/common.yaml secrets/hosts/<host>.yaml
   ~~~

4. Provision the new key to the host: `scripts/provision-host-key.sh <host>`.
5. Rebuild/activate the host and confirm its secrets decrypt.

The admin key can always re-wrap a file because it is a recipient of every ciphertext;
keep it backed up too.

rewrite, every existing clone must be re-cloned.
