# AGENTS.md — nixos

This file provides guidance to AI coding agents working in this repository.

## Purpose

NixOS system configurations for a fleet of x86_64, aarch64, and Raspberry Pi
hosts, managed with flakes and home-manager.

## Domain Glossary

- **bee-pc** — Desktop PC (x86_64, AMD, no discrete GPU)
- **bee-gpd** — GPD handheld (x86_64, AMD + NVIDIA)
- **homelab** — Home server (x86_64, Docker, NFS, Samba, Intel Arc)
- **bee-gpu-server** — GPU server (x86_64, NVIDIA, Steam remote-play client)
- **protecli-vault** — Tailscale subnet-router / egress gateway (x86_64)
- **pikvm** — Raspberry Pi 4 KVM (aarch64, cross-compiled)
- **node0**–**node4** — five-node Raspberry Pi 5 k3s cluster (aarch64); `node0`
  is the control plane, `node1`–`node3` are NVMe agents, `node4` an SD-card agent
- **rpi3** — Raspberry Pi 3B Chromium kiosk (aarch64, `nixos-raspberrypi`, SD image)
- **home-manager** — User-level config management (dotfiles, shell, packages)

## Commands

- **Rebuild local machine**: `rebuild` (shell alias for `./rebuild.sh`, auto-detects hostname, formats with alejandra, builds/switches only — it does not commit)
- **Rebuild homelab**: `rebuild --homelab` (deploys to bee@10.0.0.150)
- **Rebuild pikvm**: `rebuild --pikvm` (cross-compiles aarch64, deploys to bee@10.0.0.175)
- **Dry run**: Add `--dry-run` to any rebuild command
- **Force rebuild** (skip change detection): Add `--force`
- **Update flake inputs**: `nix flake update`
- **Format code**: `alejandra .` (never use nixfmt)
- **Deploy a host**: `nix run .#deploy -- .#<host> --skip-checks -- -L` (deploy-rs; server hosts only; `--skip-checks` avoids building `pikvm`'s aarch64 kernel on x86_64 — validate schema with `nix flake check --no-build`). The k3s nodes and `rpi3` are manual (`workflow_dispatch`) only, reached over the LAN as `pi@10.0.0.140`–`144` and `bee@10.0.0.145`.

## Architecture

All x86_64 hosts share a common module set. PiKVM and the Raspberry Pi fleet use
their own minimal configs; the RPi hosts build with the `nixos-raspberrypi`
vendor modules.

- `flake.nix` — Host definitions and flake inputs (nixpkgs 26.05, nixpkgs-unstable, home-manager, sops-nix, nixos-raspberrypi, deploy-rs, disko, flake-parts, import-tree)
- `hosts/<hostname>/` — Per-machine host aspect (for x86_64) or plain config; hardware config and host-specific settings
- `modules/` — Shared modules imported by hosts:
  - `modules/aspects/` — flake-parts aspect registry for the x86_64 fleet (see `aspects/README.md`); `common`, `desktop`, `network`, `dev-tools`, `gaming`, `nvidia`, `home-desktop`, `home-zsh`, `cli-core`, `cli-extras`, `server-base`, `k8s`, `unstable`
  - `modules/rpi/` — RPi fleet modules: `base.nix`, `k3s-common.nix`, `k3s-server.nix`, `k3s-agent.nix`, `k3s-token-sops.nix`, `node-health.nix`, `disko-config.nix`
  - `sops.nix`, `pikvm.nix`, `steam-remote-play-client.nix` — plain modules (not aspects)
- `config/` — Vendored dotfiles (MangoHUD, Rofi, Waybar, PiKVM YAML)
- `rebuild.sh` — Build script that formats and builds/switches; it does not commit

## Conventions

- Formatter is `alejandra` (rebuild.sh runs it automatically before build)
- Each host's hardware-configuration.nix is generated by nixos-generate-config — do not hand-edit
- Modules should stay composable; hosts import only what they need
- The `nixpkgs-unstable` overlay provides bleeding-edge packages when the stable channel lags
- Shared x86_64 concerns are **aspects** under `modules/aspects/` (flake-parts + `import-tree`); a host enables a capability by listing the aspect ("listed = enabled"). All five x86_64 hosts (`homelab`, `bee-pc`, `bee-gpd`, `bee-gpu-server`, `protecli-vault`) are aspect-composed. See `modules/aspects/README.md` before adding or changing one. The RPi fleet still uses plain modules pending a follow-up spec

## Guardrails

- Never modify `hardware-configuration.nix` files (auto-generated)
- `rpi3` intentionally enables SSH password authentication (preserved from its
  source config); this is a known hardening follow-up, not a bug
- Never hardcode passwords or keys in .nix files
- Test with `--dry-run` before applying changes to remote hosts (homelab, pikvm, the k3s nodes, `rpi3`)
- PiKVM and Raspberry Pi changes require cross-compilation (slow) — verify changes locally first if possible
- The k3s nodes and `rpi3` are manual-deploy only; never add them to the merge-triggered auto-deploy set (currently `homelab`, `bee-gpu-server`)
- The RPi `build-arm` lane frees runner disk first: `node0`–`node3` carry the 16K-page jemalloc overlay, which changes the Rust toolchain closure and misses every binary cache, so they build the kernel + full closure from source
- `zram-generator`'s build-time check is disabled on the k3s nodes: its test harness needs user namespaces that the ARM CI runner does not provide
